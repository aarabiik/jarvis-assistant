# JARVIS — нейросеть управляет мышью и клавиатурой

Приложение-компаньон: чат с моделью через **OpenAI-совместимый API**, у которой
есть реальные инструменты — двигать курсор, кликать, печатать, нажимать горячие
клавиши, прокручивать, запоминать точки экрана, переключать окна и **смотреть на
экран** через вторую (зрячую) модель.

Окно можно держать **поверх всех окон**: оно всегда показывает координаты
курсора, так что модель (и вы) точно знаете, где находится мышь.

## Два режима

- **Полный** — космическое окно с чатом, шапкой-реактором и панелью инструментов.
- **Мини** — маленькая плавающая панель поверх экрана (как ассистент в телефоне):
  пульсирующий реактор, поле ввода, кнопки «развернуть» и «закрыть».
  Переключение — кнопка «◱ Мини» или **Ctrl+Shift+J**, Esc в мини — вернуться.

Оформление собрано в `theme.py` (палитра, шрифты, стили), мини-панель — в
`overlay.py`.

## Возможности

- **Чат с моделью** — обычный диалог, история сохраняется на диск.
- **Инструменты (function calling):**

  | Инструмент | Что делает |
  |---|---|
  | `get_state` | позиция курсора, размер экрана, список точек |
  | `move_mouse(x, y)` | переместить курсор |
  | `click(x?, y?, button?, count?)` | клик, двойной, ПКМ |
  | `click_point(name)` | клик в сохранённую точку |
  | `save_point(name)` | запомнить текущую позицию курсора |
  | `list_points()` | список точек с координатами |
  | `type_text(text)` | напечатать текст (любой язык, без буфера обмена) |
  | `press_keys(combo)` | `ctrl+s`, `alt+tab`, `win+r`, `enter`, `f5` … |
  | `hold_keys(keys, seconds)` | зажать клавишу/комбинацию на N секунд (Shift, стрелки, Ctrl) |
  | `mouse_hold(button, seconds)` | держать кнопку мыши зажатой |
  | `drag(x1, y1, x2, y2)` | перетащить мышью (окна, файлы, ползунки) |
  | `scroll(amount)` | прокрутка колесом |
  | `wait(seconds)` | пауза (загрузка страницы и т. п.) |
  | `open_url(url)` | открыть сайт в браузере по умолчанию (`gemini`, `youtube`, любой адрес) |
  | `open_app(name)` | запустить программу: `блокнот`, `калькулятор`, `хром`, `эдж`, `телеграм` |
  | `download_file(url, filename?)` | скачать файл/установщик без браузера |
  | `list_windows()` | список окон: заголовки, размеры, какое активно |
  | `switch_window(title)` | вывести окно на передний план по части заголовка **или имени программы** (`edge`, `chrome`, `notepad`) |
  | `look_screen(question?, only_active_window?, coords?)` | снимок экрана → описание окон, элементов и текста; `coords=true` накладывает сетку координат |
  | `find_and_click(description)` | найти элемент по описанию, получить координаты и сразу кликнуть — один вызов |
  | `run_plan(steps)` | выполнить список действий подряд, без запроса к модели на каждый шаг |
  | `run_command(cmd, cwd?, timeout?)` | скрытая команда: exit code, stdout, stderr |
  | `start_session(cmd)` / `send_input` / `read_session` / `close_session` | интерактивные программы: ssh, REPL, y/n, TUI |
  | `get_screen_state()` | дерево элементов активного окна (UI Automation) |
  | `click_element(element_id?/name?)` | клик по имени или id, без координат |
  | `read_file` / `write_file` / `list_dir` / `delete_file` / `move_file` | файлы: чтение, запись, каталог, удаление, перенос |
  | `edit_file(path, old, new)` | точечная правка кода: заменить фрагмент, не перезаписывая файл |
  | `grep(pattern, path?, glob?)` | поиск по содержимому: `file:line: текст` |
  | `glob(pattern)` | список файлов по маске (`**/*.py`) |
  | `gh(args)` | GitHub CLI: repo/pr/issue/api — токен не нужен в чате |
  | `save_file(name, content, append?)` | записать текст в рабочую папку ассистента |
  | `read_file(name)` | прочитать файл из рабочей папки |
  | `list_files()` | что лежит в рабочей папке |

- **Понимание экрана** — `look_screen` делает снимок и отправляет его
  vision-модели. Основная модель картинки не видит, поэтому для зрения
  используется отдельная модель (`vision_model` в настройках).

  Что важно знать:

  - **своё окно на время снимка скрывается** — иначе ассистент видел бы
    собственный чат вместо рабочего стола. Окно возвращается **сразу после
    снимка**, ещё до запроса к vision-модели, поэтому не исчезает на всё время
    ответа (раньше могло пропасть на минуты, если провайдер тормозил);
  - **курсор рисуется маркером** (красный кружок с перекрестием) — Windows
    не включает курсор в снимок экрана, поэтому он добавляется вручную;
  - в ответе всегда приходят **точные координаты курсора, окно под курсором и
    активное окно** — текстом, а не «на глазок» по картинке;
  - если в вопросе есть «панель задач», «часы», «время», «значки», «трей» —
    к снимку добавляется **увеличенная полоса панели задач**, по ней читаются
    время и иконки;
  - модель отвечает **сначала на вопрос**, и только потом даёт контекст
    (раньше она всегда начинала с «открытые окна / активное окно»);
  - с `coords=true` (или если спросить «где кнопка») на снимок ложится
    **сетка координат экрана** — модель называет готовые (x, y) для клика,
    точность 0–3 px на тестах.
- **Переключение окон** — `switch_window("часть заголовка")` выводит нужное окно
  вперёд (с восстановлением из свёрнутого). Если заголовок не совпадает —
  ищет по имени программы: `switch_window("edge")` найдёт `msedge.exe`,
  `switch_window("chrome")` — `chrome.exe`. `press_keys("alt+tab")` — обычное
  переключение, `list_windows()` — быстрый способ узнать обстановку без
  скриншота (в списке видны заголовок, имя программы и размер).
- **Сайты и программы — за один шаг** — `open_url("https://gemini.google.com")`
  и `open_app("блокнот")` используют системный запуск Windows. Не нужно нажимать
  `win+r`, искать в «Пуске» и набирать адрес руками: «открой джимини» — это один
  вызов `open_url`, проверено 3.5 с.
- **План одним запросом** — `run_plan([...])`: 5–10 очевидных действий
  выполняются подряд на месте, без запроса к модели на каждый шаг. Проверено:
  «открой блокнот, напиши привет, сохрани файл» — один запрос, 3.2 с
  (раньше три запроса, 7.8 с).
- **Найти и нажать** — `find_and_click("кнопка Скачать")`: снимок, координаты
  и клик за один вызов. Координаты подставляются сами, отдельный `look_screen`
  ради них не нужен. Проверено: 3.0 с, промах 1 px.
- **Зажатие клавиш и мыши** — `hold_keys("shift", 2)`, `mouse_hold("left", 2)`,
  `drag(x1, y1, x2, y2)` и `click(..., modifiers="shift")`. Держит только
  указанное время и **всегда отпускает сам** — при ошибке тоже; **F12 отпускает
  немедленно**. Проверено: удержание кнопки мыши 0.60 с, стоп посреди
  10-секундного удержания — отпущено через 0.41 с, перетаскивание — 30 движений.
- **Рабочая папка** — `save_file` / `read_file` / `list_files` и окно «Файлы»:
  ассистент складывает туда планы, ссылки и код по ходу работы, они не теряются
  между запросами и не раздувают переписку.
- **Консоль без окон** — `run_command("git status")` выполняется скрыто
  (`CREATE_NO_WINDOW`): чёрное окно не выскакивает. Возвращает exit code,
  stdout и stderr; длинный вывод обрезается с сохранением начала и конца.
- **Интерактивные сессии** — `start_session("ssh user@host")`, затем
  `send_input(session_id, "y")` и `read_session(session_id)`. Работает через
  настоящий псевдотерминал (pywinpty), экран разбирается в текст (pyte) —
  видно вопросы y/n, REPL и полноэкранные TUI.
- **GitHub** — кнопка «GitHub» один раз вводит в аккаунт через `gh` (браузер +
  код в чате), дальше `gh("pr list")`, `gh("issue list")`, `gh("api …")`.
  Токен не попадает ни в переписку, ни в журнал.
- **Клики по элементам** — `get_screen_state()` показывает кнопки, поля и меню
  с именами и id через UI Automation, `click_element("Скачать")` нажимает без
  координат. Координаты остаются запасным вариантом.
- **Разрешения и журнал** — каждое действие классифицируется (safe / changing /
  dangerous / forbidden); опасное спрашивает подтверждение, запрещённое не
  выполняется, всё пишется в `journal.log`.
- **Память в файле** — правила лежат в `workspace/AGENTS.md`. В каждый запрос
  уходит только короткая инструкция «прочитай AGENTS.md» (≈1 200 символов),
  а сам файл модель читает в начале задачи и перечитывает, когда забыла.
  Редактируй `AGENTS.md` под себя — файл виден в окне «Файлы».
- **Защита от повторов** — если один и тот же вызов с теми же аргументами
  повторяется третий раз подряд, он **не выполняется**: модель получает ответ
  «смени способ». Это ровно тот случай, когда ассистент долбил `win+r`.
- **Без лимита шагов** — по умолчанию `0`, то есть ассистент работает, пока не
  закончит задачу. Число в настройках («Лимит шагов») снова включает ограничение;
  страховочный потолок — 200 шагов, чтобы цикл не был вечным.
- **Умное сворачивание** — перед вводом текста и горячими клавишами окно
  прячется **только если фокус сейчас у него самого**. Если вы уже переключились
  в другое приложение, ничего не сворачивается и не мигает.
- **Точки экрана** — сохраняйте «кнопка входа», «поле поиска» и т. п. через
  диалог «Точки» или клавишей **F8**; модель кликает по имени, а не по
  выдуманным координатам.
- **Режим подтверждения** — по умолчанию **выключен**: ассистент действует без
  вопросов. Галочка «Спрашивать перед действием» включает подтверждение каждого
  клика и ввода. Чтение состояния, снимки экрана и паузы не спрашивают никогда.
- **Работа вне рабочей папки** — по умолчанию **разрешена без предупреждения**
  (`allow_outside: true` в настройках). Если нужно вернуть строгий режим, снимите
  галочку «Работать с файлами вне рабочей папки без предупреждения» — тогда такие
  действия снова будут требовать подтверждения.
- **История чатов** — все диалоги сохраняются автоматически в папку `chats/`
  (по файлу на чат). Кнопка «История» открывает список: открыть, удалить,
  начать новый чат. При запуске подгружается последний диалог.
- **Аварийный стоп** — кнопка или **F12**; останавливает цикл после текущего шага.
- **Скриншот в сообщении** — по желанию к вашему сообщению прикладывается снимок
  экрана (галочка «Прикладывать экран к сообщению»).

## Настройка API

Кнопка **«Настройки»**:

| Поле | Пример |
|---|---|
| Base URL | `https://api.munito.ai/inference/v1` |
| API-ключ | `munitoai_...` |
| Модель | `deepseek-ai/deepseek-v4-flash` |
| Vision-модель | `zai-org/glm-5.3-flash` |
| Reasoning | `low` |
| Лимит шагов | `0` (без ограничения) |

- **Модель** — та, что ведёт диалог и вызывает инструменты.
- **Vision-модель** — та, что смотрит скриншоты в `look_screen`. Может быть
  другой, чем основная.
- **Reasoning** — `low` отключает длинные «рассуждения». Для vision-моделей это
  критично: без этого они тратят весь лимит токенов на reasoning и возвращают
  пустой текст. Пустое значение — параметр не передаётся.

Кнопка **«Проверить подключение»** запрашивает список моделей — сразу видно,
верны ли адрес и ключ.

### Текущая настройка

Приложение настроено на **munito.ai**, ключ лежит в `settings.json`.

Диалог: **`deepseek-ai/deepseek-v4-flash`** — отвечает за 1–3 секунды и
поддерживает вызов инструментов (проверено сквозным тестом: `get_state`
вызывается, результат возвращается модели, ответ приходит).

Зрение: **`zai-org/glm-5.3-flash`** с `reasoning_effort: low`.

Проверенные альтернативы для диалога (тоже с поддержкой tools, 1–3 с):

| Модель | Время ответа |
|---|---|
| `deepseek-ai/deepseek-v4-flash` | 1.4–3.1 с |
| `qwen/qwen3.8-27b` | 1.5–2.0 с |
| `zai-org/glm-5.3-flash` | 1.1–2.8 с |

⚠️ `deepseek-ai/deepseek-v4.1-flash-1017` на этом API **зависает** (таймаут без
ответа) — не используйте её. Если модель не отвечает 90 секунд, приложение
покажет ошибку с предложением выбрать другую.

Список всех моделей подтягивается в выпадающий список поля «Модель» после
нажатия «Проверить подключение».

### Какие модели видят картинки (проверено на munito.ai)

| Модель | Результат |
|---|---|
| `zai-org/glm-5.3-flash` | ✅ видит, текст распознаёт верно (1.4 с на маленьком снимке) |
| `qwen/qwen3.8-27b` | ✅ видит, текст распознаёт верно (2.5 с) |
| `lightonai/lightonocr-2-1b` | ❌ `'image' is not supported` |
| `google/gemma-4-12b` | ❌ `'image' is not supported` |
| `aleph-alpha/kolibri-1` | ❌ `'image' is not supported` |
| `munito/ocr-fast`, `munito/ocr-auto` | ❌ `model_not_found` (в списке есть, доступа нет) |

Скорость `look_screen` на этой машине: маленькое активное окно — **2–3 с**,
полный экран 1920×1080 — **7–14 с** (снимок ужимается до 1024 px по ширине,
JPEG q65, лимит 1200 токенов). Изредка провайдер отвечает дольше.

## Как ассистент понимает, что происходит на экране

1. `list_windows()` — мгновенно, без сети: заголовки окон, размеры, активное.
2. `look_screen("где курсор")` — снимок уходит vision-модели вместе с точными
   координатами курсора и названием окна под ним. Ответ начинается с прямого
   ответа на вопрос.
3. `switch_window("Блокнот")` или `press_keys("alt+tab")` — переход в нужное
   приложение.
4. Снова `look_screen(...)` — проверить, что переключились туда, куда хотели.
5. `click(...)` / `type_text(...)` — действие в уже активном окне.

Примеры вопросов, на которые инструмент отвечает:

| Вопрос | Что делает |
|---|---|
| «какой текст в этом окне?» | читает текст со снимка |
| «где курсор?» | маркер на снимке + точные координаты и окно под курсором |
| «который час на панели задач?» | добавляет увеличенную полосу панели задач |
| «какие значки в трее?» | читает правый нижний угол по увеличенной полосе |
| «где кнопка Отправить?» | сетка координат на снимке → точные (x, y) для клика |

Проверено: «где курсор» → 3–5 с, ответ «в точке (620, 310), над окном
„БЛОКНОТ ТЕСТ 555“, над словом „ТЕКСТ“»; «который час» → 3 с, ответ
«18:46 (27.10.2026)».

## Координаты элементов по снимку (сетка)

Раньше модель «на глаз» выдумывала, куда кликнуть. Теперь в режиме координат
на снимок накладывается сетка:

- линии через каждые **100 px**, подписаны жёлтым **реальными координатами
  экрана** (сверху, снизу и слева), между ними тонкие линии через 50 px;
- снимок передаётся **один к одному** (1 пиксель картинки = 1 пиксель экрана),
  поэтому цифры на сетке — это сразу готовые координаты для `click`;
- режим включается сам, если в вопросе есть «координаты», «где кнопка»,
  «нажми», «клик», «меню», «поле» и т. п., либо явно: `coords=true`.

Проверка на трёх кнопках в тестовом окне (истинные центры 425/725/1025, 322):

| Прогон | Ошибка X | Ошибка Y | Клики по координатам модели |
|---|---|---|---|
| 1 | 0 / 0 / 0 px | 0 px | 3 из 3 |
| 2 | 0 / 0 / 0 px | 0 px | 3 из 3 |
| 3 | 0 / 3 / 3 px | 3 px | 3 из 3 |
| полный экран | 0 / 0 / 2 px | 1 px | 3 из 3 |

Полный экран — 4–5 с, снимок одного окна — 2–5 с.

## Клик по неактивному окну

Первый клик в неактивное окно Windows тратит на активацию, и кнопка не
нажимается. Поэтому перед кликом приложение сначала активирует окно под
точкой (`focus_point`), и только потом щёлкает. Проверено: клик по кнопкам
в неактивном окне — 6 из 6 попаданий, в том числе после переключения на другое
окно.

Рабочий стол, панель задач и меню «Пуск» при этом не активируются — им это
не нужно и только мешает.

Если точку клика закрывает **своё окно ассистента** (оно всегда поверх),
приложение убирает его на время клика и возвращает сразу после — вместе
с фокусом в том окне, куда кликнули. Проверено: клик по кнопке под окном
ассистента нажимает кнопку, окно возвращается, 0.6 с.

## Открыть сайт или программу

| Просьба | Что вызывает модель | Результат |
|---|---|---|
| «открой джимини» | `open_url("https://gemini.google.com")` | страница открывается в браузере по умолчанию, 1 шаг, ~3.5 с |
| «открой ютуб» | `open_url("youtube.com")` | то же |
| «открой блокнот» | `open_app("блокнот")` | запускается Notepad |
| «открой калькулятор» | `open_app("калькулятор")` | запускается «Калькулятор» |

`open_url` понимает короткие имена: `джимини`/`gemini`, `ютуб`, `гугл`, `яндекс`,
`чатгпт`, `вк`. `open_app` — русские названия: блокнот, калькулятор, проводник,
хром, эдж, терминал, командная строка, телеграм, настройки, paint, word, excel.
Если программы нет в PATH, ищется ярлык в меню «Пуск».

Никакого `win+r` и поиска в «Пуске» для этого не нужно — раньше ассистент тратил
на это по 6–10 шагов и часто не доводил до конца.

## План одним запросом

Вместо «запрос → одно действие → запрос → одно действие» модель отправляет
`run_plan` со списком шагов:

```json
{"steps": [
  {"tool": "open_app", "args": {"name": "блокнот"}},
  {"tool": "type_text", "args": {"text": "привет"}},
  {"tool": "save_file", "args": {"name": "note.md", "content": "привет"}}
]}
```

Шаги выполняются подряд в приложении, результаты возвращаются одним списком.
Если шаг упал, план останавливается (`continue_on_error: true` — продолжить).
Вложенный `run_plan` запрещён. Внутри плана работают все инструменты, включая
`find_and_click`, поэтому «найди кнопку и нажми» — это тоже один шаг.

## Рабочая папка ассистента

Папка `workspace/` рядом с `app.py` — личный блокнот модели: планы, ссылки,
названия программ, куски кода. Кнопка **«Файлы»** в главном окне показывает
список и содержимое (обновляется само). Инструменты: `save_file(name, content, append)`,
`read_file(name)`, `list_files()`.

Зачем: длинная задача не тонет в переписке, а план переживает перезапуск и
новый диалог — модель может перечитать файл и продолжить с того же места.

## Консоль без окон

`run_command` запускает PowerShell скрыто — окно не появляется:

```
run_command("git status")
run_command("pip list", cwd="C:\\work\\repo", timeout=120)
```

Возвращает `exit=0`, stdout и stderr. Вывод обрезается до ~12 000 символов:
начало и конец сохраняются, середина заменяется пометкой.

Для интерактивных программ — сессии:

```
start_session("ssh user@host")          → id сессии + экран
send_input("a1b2c3d4", "y")             → экран после ответа
read_session("a1b2c3d4")                → текущий экран
close_session("a1b2c3d4")
```

Сессия — настоящий псевдотерминал (pywinpty), а экран разбирается pyte, поэтому
модель видит текст TUI (nano, htop, mc), а не поток escape-кодов. **F12** и
закрытие приложения убивают все сессии.

## GitHub

1. Кнопка **«GitHub»** в главном окне.
2. Откроется браузер и покажется код — он уже в буфере обмена.
3. Вставьте код на странице GitHub и подтвердите.

Дальше модель работает через `gh`: `gh("repo view")`, `gh("pr list")`,
`gh("issue list")`, `gh("api repos/user/repo")`. Вход и токен хранит `gh`,
в переписку и журнал токен не попадает.

Если `gh` не установлен: `winget install --id GitHub.cli -e`.
`gh` и `git` ищутся и в портативных папках `%LOCALAPPDATA%\GitHubCLI` и
`%LOCALAPPDATA%\MinGit` — без прав администратора.

## Разрешения и журнал

Уровни:

- **safe** — чтение, `dir`, `git status`, `get_screen_state`: сразу;
- **changing** — запись файлов, клики, установка, `git commit`: сразу, но в журнал;
- **dangerous** — удаление, `sudo`/`runas`, реестр, `format`, отправка данных
  наружу: только после подтверждения с точной командой. Выход за рабочую папку
  попадает сюда только при `allow_outside: false`;
- **forbidden** — список в настройках (`forbidden_patterns`, регулярки через `;`)
  плюс встроенный: `format`, `diskpart`, `bcdedit`, `mkfs` и т. п. — никогда.

Уровень повышается по контексту: `;`, `&&`, `|`, `>`, `$(`, обратные кавычки и
пути за пределами рабочей папки. Отдельно: текст из чужих файлов и страниц —
данные, а не команды; инструкции внутри («выполни», «отправь») не выполняются
без подтверждения (защита от prompt injection).

Журнал — `journal.log` рядом с `app.py`: время, инструмент, уровень, решение
(выполнено / отклонено / запрещено), аргументы и результат. Токены и пароли
маскируются звёздочками.

## Экономия токенов (по желанию)

По умолчанию **никаких сокращений**: история и результаты инструментов уходят
в модель целиком, пометок о сокращении нет.

Если захотите включить экономию — поставьте в `settings.json`
`"max_context_chars": 50000`. Тогда:

- старые ходы выбрасываются, когда история превышает лимит;
- скриншот уходит один раз и убирается из истории;
- очень длинные результаты инструментов подрезаются.

`0` (по умолчанию) — выключено. Новый диалог на каждую новую задачу всё равно
дешевле: старая история не тянется.

## Файлы рядом с приложением

- `settings.json` — адрес API, модели, ключ (**хранится в открытом виде**, это
  локальный конфиг; не выкладывайте его в публичные репозитории);
- `points.json` — сохранённые точки экрана;
- `chats/*.json` — история диалогов (по файлу на чат);
- `workspace/` — рабочая папка ассистента (планы, ссылки, код) — её видно
  в окне «Файлы»; там же файл памяти `AGENTS.md` с правилами работы;
- `journal.log` — журнал действий (кто, что, какое решение, результат);
- `secrets.json` — необязательный: `{"github_token": "..."}`, если нужен токен
  вместо входа через `gh` (файл не публикуйте).

## Как это устроено

```
app.py       — интерфейс, горячие клавиши, исполнение инструментов
llm.py       — клиент /chat/completions и цикл function calling
actions.py   — мышь, клавиатура (SendInput), хранилище точек
screen.py    — снимки экрана, vision-запрос, список и активация окон
chatstore.py — сохранение и загрузка истории чатов
workspace.py — рабочая папка ассистента (файлы и заметки)
shell.py     — скрытые команды и интерактивные сессии (PTY + pyte)
uia.py       — дерево доступности: текст экрана и клики по элементам
guard.py     — уровни разрешений, журнал, маскировка секретов
github.py    — вход в GitHub и запуск gh
```

Цикл: сообщение → модель просит инструмент → (при включённом подтверждении —
запрос разрешения) → выполнение → результат возвращается модели → следующий шаг.
Максимум шагов за один запрос задаётся в настройках: `0` (по умолчанию) — без
ограничения, любое другое число — предел на запрос. Если предел кончился —
напишите «продолжай», история сохранится и работа пойдёт дальше с того же места.

### Сочетания клавиш

Клавиши нажимаются с паузами 60 мс между нажатием и отпусканием. Без пауз
Windows часто «проглатывает» модификатор, и `win+r` не срабатывает. Проверено:
`win+r` открывает «Выполнить», `win+e` — Проводник, `alt+tab`, `ctrl+s`,
`ctrl+shift+esc` работают.

Буквы в сочетаниях отправляются виртуальными кодами (VK), а не Unicode-пакетом:
иначе `ctrl+a` приходил как просто «а» и текст не выделялся. Работает и
кириллическая запись (`ctrl+а`). Одиночный символ без модификаторов печатается
как обычный символ — раскладка учитывается.

### Умное сворачивание

Перед вводом текста и нажатием клавиш приложение проверяет, у кого сейчас фокус:

- фокус у окна JARVIS → окно сворачивается на время действия и возвращается
  (иначе текст ушёл бы в чат, а не в целевое приложение);
- фокус у другого приложения → окно **не трогаем**, действие выполняется сразу.

Проверено тестом: при активном чужом окне состояние окна не меняется
(`IsIconic = False` всё время), при активном JARVIS окно прячется и
восстанавливается.

## Безопасность

- режим подтверждения **выключен по умолчанию** — ассистент действует сразу;
  включите «Спрашивать перед действием», если хотите контролировать каждый шаг;
- работа вне рабочей папки **разрешена по умолчанию**; строгий режим включается
  снятием галочки «Работать с файлами вне рабочей папки без предупреждения»;
- F12 останавливает работу;
- действия выполняются с правами вашего пользователя; окна, запущенные от
  администратора, приложение не контролирует (ограничение Windows UIPI);
- пароли и платёжные данные модель не вводит без прямой просьбы (это прописано
  в системном промпте, но полагаться только на промпт не стоит);
- API-ключ хранится в `settings.json` открытым текстом. Если файл кому-то
  показывали — перевыпустите ключ в личном кабинете провайдера.

## Чего приложение не делает

**Не обходит капчи и антибот-защиту** (reCAPTCHA, Cloudflare Turnstile и др.).
Если на экране капча — ассистент останавливается и просит пройти её вручную.
Это осознанное ограничение: обход таких систем нарушает правила сайтов, а
приложение предназначено для личной автоматизации на своей машине.
